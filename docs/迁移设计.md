# weibo-monitor -> auto-news-monitor 迁移设计

## 核心决策
保留 `Post` 模型字段名，语义重映射到「文章」，使投递层零改动移植：
- uid=数据源key(去重命名空间)  screen_name=数据源名  mid=文章稳定ID(去重键)
- url=文章链接  created_at=发布/上市日期(tz-aware UTC)  title=标题
- text_plain=标题+摘要  image_urls=封面

## 复用(未改) 13 个模块
atomic_json/log/health/state/chats/card_store/listener/forward/bitable/
image_uploader/classifier/sender/card。DeepSeek 汽车行业分类标签正好适用。

## 新写
- src/sources/base.py   SourceFetcher 协议 + fetch_html + parse_cn_date
- src/sources/{yiche,sina,autohome}.py  三个抓取器(列表+详情摘要+封面)
- config.py / monitor.py / main.py  去微博化、简化

## 抓取层要点
- 三站均 SSR、robots 宽松、无反爬；比微博净减 ~1500 行 cookie/CLI/playwright
- 汽车之家：gb2312 编码、图片 data-src 懒加载
- 易车增量只解析首屏，不逆向翻页接口
- 站点多为日期粒度且有未来上市日期 -> 去重(mid)是主信号，时效窗口放宽到 72h
