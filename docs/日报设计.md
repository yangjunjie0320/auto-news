# 日报聚合设计

定位（2026-08-01 与用户对齐）：网站官方信息成体系但废话多 → 做骨架并压缩；
独立博主增量多但不成体系 → 账号池每天批量抓取，挂到事件体系里。
网站保持实时播报；微博不实时，只进日报。

## 流水线

```
[实时，已有]  抓取三个网站 → 分类 → 飞书卡片推送
                    ↓ 推送成功后追加一行
              state/digest/YYYY-MM-DD.jsonl

[每天定时]
  1. 读前一日网站素材
  2. 抓账号池当天时间线（34 账号各一页，随机延时；游客 cookie，
     weibo-monitor 生产同款路径）→ 分类过滤 → 微博素材
  3. LLM 聚类网站文章 → 事件（同型官方数据合并成盘点，产出压缩对比列表）
  4. LLM 匹配池内微博 → 挂载到事件 / 聚成新事件（博主先发的新闻）/ 散装观点
  5. 搜索补充：只搜池子没覆盖的事件，增量优先挑选
  6. 按热度排序 → 渲染卡片：分类卡 + 尾部「博主观点」卡（散装 top12）
```

层级：网站文章定义事件主干；池内微博是一等素材（可挂载、可成为纯微博事件）；
搜索降级为补充通道。所有微博层失败都只降级，日报照发。

## 微博搜索：2026-08-01 实测结论

用当天三个网站的真实标题造查询词，实测 `m.weibo.cn` 综合搜索：

| 结论 | 依据 |
| --- | --- |
| 游客 cookie 够用，不需要登录态 | 每个查询稳定返回 10~15 条，相关性高 |
| 用综合搜索（type=1），不用实时（type=61） | 实时的中位互动 0~5，40%~100% 零互动；综合中位互动 31~652 |
| 搜索词必须含专有名词 | 泛词「新能源汽车」15 条里只有 2~3 条与当天事件相关，其余是抽奖、科普、软文 |
| 必须按时间窗过滤 | 结果时间跨度可达 200 小时以上 |
| 必须防营销内容占位 | 「极氪9X」15 条里 6 条是明星下单营销，实际的上市定价信息只占 1~2 条 |

因此日报不依赖 weibo-monitor 的 cookie 文件、浏览器 profile 和熔断持久化，
`src/weibo_search.py` 是自足的游客态客户端。

接口差异：搜索接口的 `user.followers_count` 是 `"431.3万"` 这类格式化字符串，
时间线接口返回整数，`parse_followers` 两种都吃得下。

## 降级

微博是软依赖。限流、解析失败、超时都只让该事件少个讨论区块；整体失败退化成纯
网站日报。LLM 裁决失败退回纯规则筛选并标注「自动关联」。

## 实现（2026-08-01 已落地并试跑通过）

```
src/digest/store.py    素材 JSONL 读写（推送钩子在 sender.py，按北京时间分文件）
src/digest/events.py   事件抽取：一次 LLM 调用聚类 + 产出搜索词，失败退化为一文一事件
src/digest/weibo.py    搜索 → 硬过滤（时间窗/互动或粉丝阈值）→ LLM 挑 3 条并标角度
src/digest/card.py     按分类分卡渲染，卡内按热度（覆盖源数+微博数）排序
src/digest/runner.py   build_digest 编排 + DigestScheduler 每日定时
src/weibo_search.py    游客态微博搜索客户端
```

入口：`digest_enabled: true` 时常驻调度；`--digest-once [DATE]` 手动出一份
（配 `--dry-run` 只生成不发）。state/digest.json 记 last_digest_date 防重发。

试跑（8 月 1 日 11 篇文章）：11 事件、25 条微博讨论、3 张卡片（575B/2KB/8.5KB，
均低于飞书 28KB 上限）。发现并修复：同一条「车企销量汇总」微博被多个交付事件
重复挂载 → collect_discussions 加跨事件 mid 去重。

试跑期间 DeepSeek key 借用 weibo-monitor 的 config；正式部署要在本项目
config.yaml 配 deepseek_api_key。

## v2（2026-08-01 第二版试跑）：官方数据压缩 + 增量优先

背景判断（用户）：独立博主增量多、广告少但不成体系；官方发布成体系但废话多。
日报的定位是用网站官方信息做骨架并压缩，微博层只要官方事实之外的增量。

- 盘点合并：同型周期性官方数据（月度交付战报等）合并成一个 kind=roundup
  事件，聚类阶段直接产出压缩对比列表（points，一行一家，异常点标注）。
  提示词教训：「不同主体是不同事件」规则会压过盘点规则，必须把盘点提为
  第一步、声明为唯一允许跨主体合并的例外、并给对口示例，DeepSeek 才执行。
- 挑选反转：把事件已知事实传给挑选 prompt，声明「复述无增量」，独立博主
  一手观察优先，官方账号仅在给出新细节时入选，宁缺毋滥。
- 效果（同一天素材）：11 事件 → 4 事件；25 条微博 → 5 条全增量
  （实车体验/渠道观察/行业影响），官方战报转发与营销文案全部被淘汰；
  市场数据卡 8.5KB → 1.8KB。

## v3（2026-08-01 第三版）：账号池接入

- `src/weibo_client.py`：搜索 + 时间线 + 长文补全的统一游客态客户端
  （原 weibo_search.py 升级更名）。
- `src/digest/pool.py`：34 账号各抓一页时间线（约 3 分钟），复用 classifier
  过滤广告/无关，产出 kind=weibo 素材。
- `src/digest/events.py` 匹配阶段：drop（纯复述）/ 挂载 / 新事件 / 散装观点
  四选一。实测 98 条池内微博 → 约 6 条散装 + 若干挂载与纯博主事件
  （极狐交付、蔚来ET5T谍照、smart精灵2号、F1第二站等网站未报的新闻）。
- 发送断点续传：整副卡片先落盘 outbox，逐张记进度，部分失败后重试从断点
  续发同一副卡片（LLM 生成不确定，重建再发会重复）。

匹配阶段三个已踩过的失败模式。前两个提示词治不住（多轮实测模型反复无视），
最终都落成 `_apply_matches` 里的确定性代码防御：
1. 播报数字的微博被成批挂上盘点（提示词明令 drop 也没用）→ 代码层：
   挂向 roundup 事件的 assignment 一律按复述丢弃，盘点保持纯数字表。
2. 纯语义错挂：标题抄对了、内容却是另一家公司的新闻（红旗帖挂到一汽-大众）
   → 词面防线 `_plausibly_related`：微博与事件（标题+points+成员标题）共享
   ≥2 个二元词组才允许挂载，否则落散装。
3. 模型给自己新开的事件续编号塞进 assignments，编号错位 → assignments
   必须回显 event_title，解析校验，对不上作废。

最终一天（2026-08-01）实测：11 篇网站文章 + 99 条池内微博 → 15 事件
（盘点 1 + 网站 3 + 纯博主 11）+ 4 条挂载 + 3 条搜索补充 + 散装 1 条，
7 张卡片全部低于飞书上限，已实发验证。

## 飞书文档（2026-08-01 新增）

每期日报同时写一篇飞书文档（`src/digest/doc.py`）：卡片是当天在群里扫的
摘要，文档是可回看、可检索的完整档案（散装观点全量收录，不截断）。
- 发卡前建档，链接进首卡；建档失败卡片原样发（软依赖）。
- 文档创建后自动开租户内链接分享（drive v2 permission_public，
  link_share_entity=tenant_readable）；该步失败仅告警，需手动开分享。
- 需要应用权限：docx:document + drive 分享权限（当前应用已具备，实测通过）。
- 块结构：导语 quote、分类 heading2、事件 heading3（标题即原文链接）、
  要点 bullet、来源行 text、微博讨论 quote。分批 50 块写入。

## v4（2026-08-07）：详讯/短讯二分

需求（与用户对齐）：事件二分取代按分类分卡。详讯 = 有网站文章、或 ≥2 条
微博指向同一事件（盘点恒为详讯）；短讯 = 单条微博的事件 + 散装观点，
合并成简短列表。详讯五要素：无宣传性表达的标题、叙述性中文缩写 bullet、
逐条对应的英文缩写、图片（网站封面图 + 微博配图）、原文全文。

展示分层：卡片只放标题 + 中文缩写（+文档链接）；英文对照、图片、原文只进
飞书文档，文档里默认折叠（h4 folded 小节），标题 + 中文默认展开。

- 数据链路：DigestRecord 增加 full_text / image_urls（旧 JSONL 靠默认值
  兼容）；sender 钩子不再丢弃 Post.full_text 和封面图；weibo_client 解析
  pics（large 优先，限 9 张）；pool 透传微博全文与图。
- `src/digest/detail.py`：详讯精修，每个详讯一次 DeepSeek 调用（聚类每批
  40 篇只喂 120 字摘要，塞不下全文，所以单独调用）。输出成对对象
  {"zh","en"} 从格式上杜绝中英错位；roundup 只喂 points 不喂全文。
  失败降级：brief=None 时退回聚类标题 + points/摘要要点，无英文小节。
  不改 event.title——discussions 字典以它为键。
- 文档图片：预下载（复用 image_uploader 的白名单校验，失败的 URL 不建
  占位块）→ 占位 image 块（type 27）→ drive upload_all(parent_type=
  docx_image) → patch replace_image 绑定。需 drive 上传权限，缺权限降级
  无图。每事件默认最多 4 张（digest_max_images_per_event）。
- 配置：digest_detail_enabled（一键回退）、digest_doc_images_enabled、
  digest_max_images_per_event 等，见 config.example.yaml。

## 已按试跑结论定下的设计点

- 零互动微博不能直接丢：刚官宣的事件（40 分钟内）互动普遍为 0，改为
  「互动 ≥5 或粉丝 ≥10 万」任一达标即入候选
- LLM 挑选提示词明确「按信息量不按互动量」：热度排序会把明星营销顶到最前
  （极氪9X 的 15 条里 6 条是明星下单）
- 发送时间默认 08:00 发前一自然日（digest_send_time 可配）
